# Contribuindo
1. Abra uma issue descrevendo objetivo, critérios de aceite e teste de regressão.
2. Faça mudanças pequenas sem incorporar código ou imagens de projetos de referência.
3. Execute `npm test` e atualize docs/specifications ou uma ADR quando mudar invariantes.
4. Toda mudança em persistência deve incluir teste de falha e estratégia de migração.
5. Nunca inclua texto de manuscritos reais em issues ou logs públicos.
